# 论文材料

## 建议题目

基于 Spark 的多数据集电商行为分析与可视化平台设计与实现

## 摘要素材

针对传统单数据集 Spark 分析程序在数据接入、字段耦合、任务可追踪性和结果覆盖方面的问题，本文设计并实现了一套基于 Java 17、Apache Spark、Hive、MySQL 与轻量 REST 服务的电商分析平台。系统通过 Dataset Manager 登记数据源，利用 Schema Mapping 将异构 CSV 转换为统一行为或订单模型，并根据已确认字段动态判断可用分析能力。Spark 分析采用独立子进程执行，任务状态、日志和结果索引持久化到 MySQL，大规模标准数据按 `dataset_id` 写入 Hive，分析结果按 `dataset_id/job_id` 保存历史版本。系统在淘宝 100,150,807 条行为记录和订单样本上完成验证；淘宝总记录数、用户数、PV、购买数及购买用户数与 Legacy 基准完全一致。结果表明，该方案在保留既有分析口径的同时，提高了数据集扩展性、任务可观测性和结果可追溯性。

关键词：Apache Spark；电商行为分析；数据集适配；Hive；MySQL；结果版本化

## 研究问题

1. 如何把只适配固定五列 CSV 的程序扩展为多数据集平台？
2. 如何在不重写已验证指标口径的情况下完成标准模型迁移？
3. 如何让长时间 Spark 任务可追踪、可失败恢复且结果不被覆盖？
4. 如何证明迁移后的指标和数据隔离真实有效？

## 设计要点

- 以 B 为唯一代码主线，A 只读复用数据和历史资料。
- 将源字段与分析逻辑之间加入 Mapping、Capability 和 Adapter 三层。
- 以 Hive 存储标准大表，以 MySQL 存储平台元数据。
- 使用子进程隔离 Spark 任务，记录 PID、退出码和日志。
- 使用不可覆盖的结果版本和 latest SUCCESS 查询。
- 在现有 DashboardServer 上增量扩展 API，保持 Java 技术栈统一。

## 可作为工程创新点的内容

以下属于工程设计贡献，不应夸大为算法原创：

1. 字段确认驱动的动态能力启停。
2. 源数据适配器与标准模型解耦分析模块。
3. `dataset_id` Hive 分区与 `dataset_id/job_id` 结果版本的双层隔离。
4. 任务失败可审计、数据集可重试、latest SUCCESS 稳定读取。
5. 大文件原地注册，避免 3.67GB 数据复制和重复预扫描。

## 实验设计

- 单元层：Mapping、Capability、Adapter、Hive DDL。
- 泛化层：淘宝行为样本与订单样本。
- 持久化层：真实 MySQL 建表、CRUD、重启恢复。
- 大数据层：正式淘宝 100,150,807 行全量执行。
- 回归层：五项 Legacy 指标逐项比较。
- 系统层：Dataset 到 Dashboard 的完整链路。

## 核心实验结果

| 指标 | 结果 |
|---|---:|
| 正式记录数 | 100,150,807 |
| 用户数 | 987,994 |
| PV | 89,716,264 |
| 购买数 | 2,015,839 |
| 购买用户数 | 672,404 |
| 复购用户数 | 443,858 |
| 复购率 | 66.01% |

五项回归指标与 Legacy 差值均为 0。全模块正式任务耗时约 3 分 11 秒；单模块重跑约 1 分 56 秒，具体时间与本机资源有关。

## 限制与展望

- 当前漏斗没有 session_id，只能解释为阶段汇总。
- 当前 DashboardServer 无生产级认证和 TLS。
- MySQL 与 Hive/文件之间没有分布式事务。
- 当前是单机本地 Spark 调度，尚未接入集群队列。
- 未来可增加 Schema 演进、数据质量规则、任务取消、权限体系和 Spring Boot 服务层。
